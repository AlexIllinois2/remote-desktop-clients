## 去掉 aRDP 旋转后宽高被限制成"门缝"的问题

用户反馈：旋转后 aRDP 主动限制远端宽高且限制错，竖屏尺寸的远端桌面留在横屏上成"门缝"，要求去掉限制、让用户自己缩放。

根因：`RemoteRdpConnection.startRdpConnection()` 原来用 `canvas.getRemoteWidth(canvas.width, canvas.height)` 按设备视口推导远端分辨率（NATIVE_LANDSCAPE→max(视口)、NATIVE_PORTRAIT→min(视口)、默认→viewWidth），而 `correctAfterRotation()` 对 RDP 是空实现（旋转时不重请求分辨率），于是竖屏连接的远端桌面尺寸在旋转后留在横屏上。

改动（`bVNC/src/main/java/com/iiordanov/bVNC/protocol/RemoteRdpConnection.kt`）：只用 `connection.rdpWidth/rdpHeight`（未配置为 0），偶数化后传入；删掉按设备视口推导的两行。

安全性静态验证（读 freerdp 树 `remoteClientLib/jni/libs/deps/FreeRDP/client/Android/Studio/freeRDPCore/.../domain/BookmarkBase.java`）：
- `ScreenSettings.getWidth()/getHeight()` 均先调 `validate()`，且 validate **就地改写** width≤0→1024、height≤0→768；`LibFreeRDP.connect()` 用 `String.format("/size:%dx%d", getWidth(), getHeight())` 拼参数。
- 传 0 → 连接按 1024×768，随后 `OnSettingsChanged(1024,768)` 与书签读数一致 → 直接 reallocateDrawable，**不会** saveConnectionSettings + REINIT_SESSION，无死循环风险。
- 书签里已存的 CUSTOM 分辨率（如 1920×1080）仍被 `connection.rdpWidth` 读回并生效。

副作用（需向用户说明）：设置里分辨率下拉的 native landscape/portrait、automatic、fitscreen 选项对初始连接不再有效（一律走 0→1024×768），只有 Custom + 自定义宽高有效；未动 UI，因为 `rdp_geometry` 数组有 30+ 语言翻译版，裁剪条目会破坏 position→RDP_GEOM_SELECT_* 索引映射。SPICE 路径不受影响（getDesiredWidth/Height 只被 SPICE 用，getRemoteWidth/Height 已无 RDP 之外调用方）。
